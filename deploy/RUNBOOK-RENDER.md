# Runbook: Render

Render builds this repository with the root `Dockerfile`. The app is a single FastAPI process
serving the built React frontend, backed by one SQLite database plus uploaded source files.

## Why the deploy can fail at startup

Render injects the `RENDER` environment marker. On any public PaaS marker, the app refuses to
boot unless one access gate is configured. The failure looks like this:

```text
Refusing to start with no access gate on a deployment that requires one (detected: RENDER).
Set BASIC_AUTH_USER + BASIC_AUTH_PASS ...
```

That is intentional. Without the gate, anyone with the Render URL can use write/delete routes.

## Blueprint deployment

The root `render.yaml` defines the Docker web service, a `/data` persistent disk, and Basic
Auth:

| variable | source |
| --- | --- |
| `BASIC_AUTH_USER` | `admin` in `render.yaml` |
| `BASIC_AUTH_PASS` | generated by Render; retrieve/rotate it in the service Environment tab |
| `LEADLENS_CORS_ORIGINS` | empty string, because frontend and API are same-origin |
| `LEADLENS_DATA_DIR` | `/data`, matching the attached disk mount |

The service keeps `numInstances: 1` because the app writes to one SQLite file.

If you already created the service manually instead of from the Blueprint, either convert/sync
the Blueprint in Render or add the same variables by hand in the existing service's Environment
tab. A commit alone does not create secret environment variables on a manually configured
service.

## Persistent storage

The Docker image defaults `LEADLENS_DATA_DIR=/data`. Render's normal filesystem is ephemeral,
so the Blueprint attaches a disk at `/data`; this keeps `leadlens.db`, `uploads/`, and
`previews/` together on persistent storage.

After enabling the disk, test persistence:

1. Deploy.
2. Upload a small file.
3. Deploy again.
4. Confirm the upload history and dataset are still present.

## Verify the gate

```bash
curl -si https://<service>.onrender.com/api/health | head -1
curl -si https://<service>.onrender.com/ | head -5
```

`/api/health` should return `200`. The dashboard route should return `401` with a
`WWW-Authenticate: Basic` header until you provide the Basic Auth credentials.
